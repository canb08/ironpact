# X9 review captures

All PNGs are 375 × 812, device scale 1, reduced motion enabled, with the same mobile Safari user agent. Captured with the installed Chromium browser; native iOS behaviour is not claimed.

`before/` uses the unmodified production components from main at `40b68cc8d78f6d1c1dec02f76a1cad9e869bc317`, rendered with the isolated Repo fixture. No explainer or Today name prompt existed: those before captures show the original Today screen. `profile.png` shows the original combined crew/profile form.

`after/` is generated by `tests/e2e/p9-onboarding.spec.ts`, using `tests/e2e/fixtures/x9.html`. The fixture renders the real AppShell, router, AuthGate and feature screens with a deterministic Repo contract. The normal mock app is already signed in and in a crew, so cannot exercise first-run setup.

**Today name prompt is an integration preview.** Only the test fixture mounts it on Today. Production `src/features/floor/FloorScreen.tsx` is outside X9's allowlist; the PR requests that mount from the Lead. The screenshot and test do not claim that the live Today screen already includes it.

Flow stages: install → sign-in (email/code) → crew choice → name/colour/target → three-card guide → Today. Crew/profile writes complete when the guide is finished or skipped; failed join/profile writes keep the flow retryable while the setup screen stays mounted. The profile write continues if the existing gate redirects during crew creation; see the PR's contract request concerning an early redirect and failed profile writes.

Run `npx playwright test tests/e2e/p9-onboarding.spec.ts` on the repository's configured browser projects to regenerate the after captures and run the accessibility checks. Locally, an external temporary Playwright config selected `/usr/bin/chromium` because bundled Playwright browsers were unavailable. Screenshot paths are intentionally under the ticket's `tests/e2e/**` allowlist.
