## Why
`docs/BOARD.md` Parked, the friend's Claude's diagnosis (2026-11-02): `AuthGate` is rendered **next to** `<RouterProvider>` in `src/App.tsx` and returns `null`. Its first pass awaits `repo.q.myCrew()` before it redirects. Meanwhile the router has already painted the Floor, so e2e `reachFloor` returns, and the late redirect to `/install` (or `/sign-in`, `/crew/new`) detaches the Floor's links. That is the remaining p1-demo / p1-flight Pixel 7 flake. It is also a real UX flash on first launch: the Floor, then the install screen.

A previous try (deciding the install gate before the crew read) made it worse and broke `SignInScreen.test.tsx`. Don't reorder the gate's rules. Hold the first paint instead.

## Scope
1. `AuthGate` wraps the router (`<AuthGate><RouterProvider router={router} /></AuthGate>`). It renders its children only once the **first** pass has settled: either `destination()` returned `null`, or the `router.navigate()` it started has landed on the target. Until then it renders nothing (the shell background shows; no new copy).
    - Later passes (sign-in or sign-out, crew joined, route changes) keep today's behaviour and **never** unmount the children again.
2. `destination()` and its rule order stay exactly as they are. Keep the `again` / hop loop / `lastTarget` logic. Pure refactor of *when* children show.
3. Failure safety: if `myCrew()` rejects or takes longer than 3 s, show the children anyway (as today), so a broken DB can never trap the user on a blank screen.
4. Tests (`tests/unit/features/auth/AuthGate.test.tsx`, new):
    - First launch, not installed → `/install` is the first route rendered; the Floor never mounts.
    - Signed in with a crew → the Floor renders after one pass.
    - Signed in, no crew → `/crew/new` first, no Floor flash.
    - Slow `myCrew` (fake timers past 3 s) → children render.
    - Sign-out later → children stay mounted and the redirect still happens.
    - `SignInScreen.test.tsx` stays green unchanged.
5. `tests/e2e/helpers.ts`: if `reachFloor`'s install-click workaround is no longer needed, leave it in (harmless). Don't weaken any wait.
