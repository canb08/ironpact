# H6 · Floor stops blanking on live updates (+ MIN double-toast guard)
**Lane:** E (friend's Claude · friend's Codex; lane C engines out of usage) · **Model:** Codex · GPT-6.1 Sol, High · **Branch:** `H6-work` · **Starts after:** P4H (#54) merged · **Why:** BOARD "Parked → Flaky e2e" (friend's Claude diagnosis, 2026-11-02)

## Why
`useRepoQuery` (`src/features/floor/useRepoQuery.ts`) builds a new store with `value = undefined` every time its deps change. FloorScreen passes `[repo, tick, crewTick]` (`FloorScreen.tsx:74`), so every crew delta pull (P3E) and every write (`tick`) blanks the Floor to its `aria-busy` shell and remounts every button. Users see a flicker; CI sees it as `warmLazyRoutes` (`tests/e2e/helpers.ts:75`) clicking a `Weight` link that is "detached from the DOM" on Pixel 7 (`p1-demo`, `p1-flight`, seen on #49, #48, #52).
A keep-last-value fix was tried by the friend's Lead: it stopped the detach, but locally `p1-demo` on Pixel 7 then showed the MIN "logged" toast **twice** (strict-mode violation). So the fix must also make one MIN tap produce exactly one toast.

`AGENTS.md`. `src/features/floor/useRepoQuery.ts`, `FloorScreen.tsx` (`onMin`, `undoMin`, line 74), the toast host behind `showToast` in `src/ui/`, `tests/e2e/helpers.ts` (`warmLazyRoutes`), `tests/e2e/p1-demo.spec.ts`, `tests/e2e/p1-flight.spec.ts`. Every other caller of `useRepoQuery` (grep it).

## Scope
1. `useRepoQuery` keeps the last delivered value across a deps change (e.g. a `useRef` seeded into the new store) so the screen never drops back to `undefined` once it has data. First load is still `undefined`. A changed `repo` (sign-out / account switch) **must** reset to `undefined`: no data from the previous user is ever shown.
2. Find why one MIN tap can show two toasts once the Floor stops remounting (toast host, `onMin` re-entry, or a StrictMode double effect) and fix the cause. One tap → one toast, also on a double-tap.
3. Unit tests: (a) value kept across a `tick` change and replaced when the new query delivers; (b) a `repo` change resets to `undefined`; (c) MIN double-tap → one `logMin` call, one toast.
4. Leave `warmLazyRoutes` as it is: the fix must make it pass, not the test.
