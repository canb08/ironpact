## Scope (FEEL §4 "Proof")
1. **Migration `0012_proof.sql`:**
   - `proof_cards` (id, crew_id, day date, kind `lift|run|muay_thai`, `together` bool, caption ≤80, created_by, created_at, deleted_at).
   - `proof_links` (card_id, entry table + entry id, user_id): links each person's entry for the card.
   - `proof_photos` (id, card_id, user_id, storage_path, width, height, bytes, created_at, deleted_at): at most 1 per user per card.
   - RLS: crew members read; the owner writes and deletes their own rows. Grants follow L-rules from H5 (0011 default privileges).
   - A private storage bucket `proof`, path `<crew_id>/<card_id>/<user_id>.jpg`, with storage policies that let only that crew read and only the owner write and delete. 5 MB server-side limit; jpeg/webp only.
2. pgTAP: a stranger can't read cards, photos or the bucket; a partner can read but not delete the other person's photo; the 1-photo-per-user-per-card rule holds.
3. **Data layer:**
   - repo methods `proof.listCards(month)`, `proof.createOrJoinCard({kind, day, together, entryRef})` (joins the partner's card for the same day + kind when together), `proof.setCaption`, `proof.addPhoto(cardId, blob)`, `proof.removePhoto`.
   - Photos go into the **outbox** (IndexedDB blob, then upload when online; retry rules like sets). Signed URLs (short-lived) are used for display and cached in memory only.
   - Mock adapter support (object URLs) so e2e works offline.
4. **Client image prep** in `src/core/image.ts` (pure where possible): decode → longest side 1600 px → JPEG 0.8 via canvas (strips EXIF/GPS) → reject >5 MB after encoding. Unit-test the size maths.
5. The CI functions check still asserts exactly the three functions (no new edge function).
