## Scope
1. `supabase/migrations/0002_rls.sql`
   - `is_crewmate(other uuid)` (security definer, `search_path = ''`, stable): true when both users are **current** members (`left_at is null`) of a shared crew.
   - Policies on **every** `public` table per §4.4: owner full CRUD on own rows (insert/update `with check (user_id = auth.uid())`); crewmates **read only**; bodyweight readable by crewmates **only when** the owner's `profiles.show_bodyweight = true`; `export_tokens.token_hash` never selectable by any client role (no select policy on the table at all — listing goes through the RPC); server-only tables (`invite_attempts`, `push_log`, `crew_weeks` writes, `nudges` writes, …) get no client write policy.
   - Global exercises (`owner_id is null`) readable by every authenticated user.
2. `supabase/migrations/0003_rpc.sql` — `security definer`, `search_path = ''`, `revoke all … from public, anon`, `grant execute … to authenticated` only where meant:
   - `create_crew(name text, tz text)` → crew id; caller becomes `owner`.
   - `create_invite(crew_id uuid)` → the **plain 10-char Crockford base32 code** (store only `sha256` hex of the normalised code; 7-day expiry; single use; D3).
   - `redeem_invite(code text)` per E4.3 (normalise: uppercase, strip `-`/spaces, map `I L → 1`, `O → 0`; rate-limit via `invite_attempts`; expired/used/revoked → error whose message the UI maps to "Code's dead. Ask for a new one."; respects `max_members`).
   - `leave_crew(crew_id uuid)` (sets `left_at`; spec §6 Phase 3 needs it, cheap to add now).
   - `create_export_token(label text)` → returns the plain token **once** (`spx_` + 43 base64url chars from 32 random bytes); stores sha256 hex; max **3 active** per user (4th → error).
   - `revoke_export_token(id uuid)` (own tokens only), `list_export_tokens()` → id, label, created_at, last_used_at, revoked_at — **never** the hash (D22).
3. **Fix from A2 review:** when a session's `local_date` changes (S15 day editor), its child rows (`sets`, `cardio_entries`, `martial_entries`, `min_entries`) must move to the new date in the same transaction. Add an `after update of local_date on sessions` trigger in `0003_rpc.sql`.
4. `supabase/tests/rls.test.sql`, `invites.test.sql`, `export_tokens.test.sql` (pgTAP, use `tests.authenticate_as`-style helpers or `set local role authenticated` + `request.jwt.claims`). Must prove at minimum (§6 Phase 1 DoD + §1.3):
   - A cannot insert/update a row with B's `user_id`;
   - A reads crewmate B's sets; non-member C reads **nothing** of A or B;
   - B's bodyweight hidden from A while `show_bodyweight = false`, visible when true;
   - an invite can't be redeemed twice, after expiry, or after revoke; the rate limit trips;
   - `token_hash` is never selectable (direct select errors or returns nothing for `authenticated` and `anon`); A can't revoke or list B's tokens; 4th active token rejected;
   - `anon` can't read any table;
   - a former member (`left_at` set) loses read access;
   - editing a session's date moves its sets.
