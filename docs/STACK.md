## A5 Edge Function tools (2026-10-26)

| Tool / package | Exact version |
|---|---|
| Deno (CI checks and integration tests) | `2.9.8` |
| `jsr:@supabase/supabase-js` | `2.118.0` |

Pins verified against the [official Deno v2.9.8 release](https://github.com/denoland/deno/releases/tag/v2.9.8) and [Supabase's JSR package](https://jsr.io/@supabase/supabase-js@2.118.0). The function imports `jsr:@supabase/supabase-js@2.118.0` directly; prerelease package versions are excluded. CI installs Deno with the [official setup action](https://github.com/denoland/setup-deno) (`v2`) and runs `deno check` plus `deno test --no-config --no-lock --allow-env --allow-net --allow-read=tests/fixtures/export supabase/functions/export/index.test.ts`. Read access is limited to the frozen golden fixtures.

After pgTAP, CI restarts a [local Supabase stack](https://supabase.com/docs/reference/cli/supabase-start), including Auth, PostgREST and Kong, and runs `supabase functions serve` with the checked-in JWT verification settings. [Local connection parameters](https://supabase.com/docs/reference/cli/supabase-status) are read into a private runner-temporary file, mapped to the test environment and masked. CLI and function logs stay private; failure output lists only container names, states and ports. No hosted credentials are required, and cleanup runs even when tests fail.
